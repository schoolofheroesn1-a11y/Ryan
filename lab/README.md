# Лаборатория педагогических технологий

Открытая библиотека практических педагогических решений и площадка для испытаний образовательных технологий. Учитель находит не просто материал, а способ решить свою задачу — с инструкцией, затратами времени, ограничениями и понятным статусом проверки.

- Исследование рынка и гипотезы: [`docs/research.md`](docs/research.md)
- Продуктовая архитектура, модель данных, система доверия: [`docs/product.md`](docs/product.md)

## Возможности MVP

- **Библиотека решений** с полнотекстовым поиском (русская морфология) по названию, описанию, задаче, шагам, тегам и примерам; 11 комбинируемых фильтров, сортировка, пагинация, сброс фильтров и пустое состояние.
- **Страница материала** с постоянным URL: задача, аудитория, ресурсы, шаги, промпты, пример, время и стоимость, ограничения, результат, источники и лицензия, статус проверки, отзывы, похожие материалы. Копирование инструкции и промптов, «Поделиться», избранное, скачивание вложений.
- **Лаборатория испытаний**: вопрос, гипотеза, условия, одинаковые задания, критерии с весами (фиксируются до результатов), таблица оценок по каждому критерию, раздельные измерения, критические ошибки, выводы и порядок воспроизведения.
- **Фишки и кейсы** — отдельный каталог коротких практических решений.
- **Профили авторов**, **форма публикации** с черновиками, валидацией и вложениями, **личный кабинет** (избранное, публикации, история статусов, отзывы, профиль).
- **Редакция**: очередь модерации, решения с комментарием автору, статусы проверки с серверной проверкой критериев, редактор исследований, модерация отзывов, жалобы, теги и категории, пользователи и роли, журнал действий.

## Стек и почему он

| Решение | Обоснование |
|---|---|
| Next.js 16 (App Router), TypeScript | серверный рендеринг для SEO, серверные действия вместо отдельного API, один язык для всего кода |
| Tailwind CSS 4 + собственные компоненты (`src/components/ui`) | токены цвета/размеров в `globals.css`; компоненты на нативных элементах (`details`, `fieldset`, `label`) доступны без JS и без лишних зависимостей |
| PostgreSQL + Prisma 6 | реляционная модель, миграции, встроенный полнотекстовый поиск с русским словарём — без внешнего поискового сервиса |
| Собственная серверная аутентификация (bcrypt, httpOnly-cookie, сессии в БД) | не требует внешних провайдеров и ключей; сессии можно отозвать (блокировка) |
| Zod | одинаковая валидация в формах и сервисах |
| Локальное хранилище файлов за проверкой прав | бесплатно; интерфейс `src/server/storage.ts` заменяется на S3-совместимый клиент |
| Vitest + Playwright | модульные/интеграционные тесты на реальной PostgreSQL и сквозные сценарии в браузере |

Внешних платных API и ключей нет.

## Структура проекта

```
prisma/
  schema.prisma          модель данных
  migrations/            миграции (включая tsvector + GIN-индекс)
  seed.ts                справочники, служебные аккаунты, демо-данные
  purge-demo.ts          удаление демо-данных
  demo/                  содержимое демо-материалов и учебных испытаний
src/
  app/                   страницы (App Router) и серверные действия (app/actions)
  components/            интерфейс; components/ui — базовые компоненты, components/forms — формы
  lib/                   чистая логика: валидация, статусы проверки, расчёт оценок, параметры поиска, подписи
  server/                сервисы с проверкой прав: materials, search, research, community, users, taxonomy, attachments, auth
scripts/reset-test-db.ts пересоздание тестовых баз (только *_test / *_e2e)
tests/unit, tests/integration, tests/e2e
docs/                    исследование и продуктовая архитектура
```

Правило: вся проверка прав — в `src/server/*` (функции принимают `actor`). Серверные действия только разбирают форму и вызывают сервис, поэтому обойти проверку прав прямым вызовом действия нельзя.

## Локальный запуск

Требования: Node.js ≥ 20.9, PostgreSQL ≥ 14.

```bash
cd lab
cp .env.example .env            # укажите DATABASE_URL
npm install                     # также выполняет prisma generate
createdb pedlab                 # или CREATE DATABASE pedlab;
npm run db:migrate              # применить миграции
npm run db:seed                 # справочники, админ и демо-данные
npm run dev                     # http://localhost:3000
```

Аккаунты после `db:seed` (только для локальной разработки):

| Роль | Почта | Пароль |
|---|---|---|
| Администратор | `admin@example.org` (или `SEED_ADMIN_EMAIL`) | `admin-demo-password` (или `SEED_ADMIN_PASSWORD`) |
| Редактор (демо) | `editor@example.org` | `editor-demo-password` |
| Автор демо-материалов | `demo-author@example.org` | `author-demo-password` |
| Учитель (демо) | `teacher@example.org` | `teacher-demo-password` |

## Проверки и тесты

```bash
npm run lint          # ESLint
npm run typecheck     # генерация типов маршрутов + tsc
npm test              # модульные и интеграционные тесты (база TEST_DATABASE_URL, по умолчанию pedlab_test)
npm run build
npm run test:e2e      # Playwright на production-сборке; база E2E_DATABASE_URL (pedlab_e2e) пересоздаётся
```

Перед первым запуском тестов создайте базы `pedlab_test` и `pedlab_e2e`. Скрипт сброса откажется работать с базой без суффикса `_test`/`_e2e`. Для e2e нужен Chromium для Playwright (`npx playwright install chromium`, если его нет в системе).

## Развёртывание

Подходит любой хостинг Node.js с PostgreSQL (VPS, Docker, PaaS).

1. Создайте базу PostgreSQL и задайте переменные окружения из `.env.example`: `DATABASE_URL`, `APP_URL` (публичный https-адрес), `UPLOAD_DIR` (постоянный том), `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` (длинный случайный пароль), `SEED_DEMO=false` для чистого запуска.
2. Сборка и миграции:
   ```bash
   npm ci
   npm run build
   npm run db:migrate
   npm run db:seed        # создаст справочники и администратора
   npm start              # порт задаётся PORT или -p
   ```
3. Поставьте перед приложением обратный прокси с HTTPS (cookie сессии в production помечается `Secure`). Ограничьте размер тела запроса ≈ 11 МБ (вложения до 10 МБ).
4. Настройте резервное копирование базы и каталога `UPLOAD_DIR`.
5. Если сайт запускался с демо-данными — удалите их перед публичным открытием: `npm run db:purge-demo`.

**Бессерверные платформы** (например, Vercel): локальная файловая система там не постоянна — замените `src/server/storage.ts` на S3-совместимое хранилище (функции `putFile`, `getFile`, `removeFile`, `hasFile`). Ограничение попыток входа (`src/server/users.ts`) хранится в памяти процесса — при нескольких экземплярах вынесите его в Redis или на уровень прокси.

## Ограничения и следующие приоритеты

Ограничения MVP:
- конкурентный анализ сделан без доступа к сайтам конкурентов (см. `docs/research.md`);
- нет восстановления пароля и подтверждения почты (нужен почтовый сервис);
- нет полноценного редактора форматирования (текст с абзацами);
- антиспам — только ограничение жалоб и попыток входа;
- все демо-материалы имеют статус «Не тестировалось», испытания — учебные примеры с условными данными.

Следующие приоритеты:
1. Провести реальные испытания (2–3 инструмента подготовки заданий) и интервью с учителями по гипотезам.
2. Подтверждение почты, восстановление пароля, уведомления автору о решении модерации.
3. Аналитика поисковых запросов (какие задачи ищут и не находят) для планирования контента и испытаний.

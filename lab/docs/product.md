# Этап 2. Продуктовая архитектура

## Аудитория MVP

Главная аудитория — **учителя-практики**. Методисты, новаторы и авторы обслуживаются через те же функции (испытания, публикация), но отдельных сценариев для них в MVP нет.

## Ключевые сценарии

| # | Сценарий | Где реализован |
|---|---|---|
| 1 | Найти решение по задаче через поиск | `/`, `/library?q=` — полнотекстовый поиск PostgreSQL с русской морфологией + поиск по подстроке |
| 2 | Сузить результаты фильтрами и сбросить их | `/library` — 11 комбинируемых фильтров, счётчик, сброс, пустое состояние |
| 3 | Понять материал и применить его | `/m/[slug]` — 13 разделов, копирование шагов и промптов, «Поделиться», вложения |
| 4 | Понять, насколько можно доверять | бейдж статуса + `/methodology#statuses` + связанное испытание |
| 5 | Сохранить в избранное | кнопка на странице материала, вкладка «Избранное» в `/me` |
| 6 | Опубликовать свой материал | `/submit` → черновик → «На модерации» → решение редакции → история статусов в `/me` |
| 7 | Отзыв и сообщение об ошибке | форма отзыва (с модерацией) и жалобы на странице материала |
| 8 | Модерация и управление | `/admin/*` |
| 9 | Испытание инструмента | `/admin/research/[id]`: участники → критерии → фиксация → результаты → ошибки → публикация |

## Структура разделов

```
/                     главная: поиск, задачи, проверенные решения, испытания, кейсы, методика, CTA
/library              библиотека решений (все типы)
/practice             фишки и кейсы (TIP, CASE) — тот же каталог с фиксированными типами
/m/[slug]             страница материала (постоянный URL)
/research             лаборатория испытаний, фильтр по виду проверки
/research/[slug]      отчёт об испытании с таблицей результатов
/methodology          критерии статусов, шаблон оценки, правила испытаний
/authors/[id]         профиль автора
/submit               форма публикации
/me                   кабинет: избранное, публикации (черновики/модерация/история), отзывы, профиль
/me/materials/[id]/edit  редактирование своего материала
/admin                очередь модерации; materials, research, reviews, reports, taxonomy, users*, log*
                      (* — только администратор)
```

## Модель данных

Prisma-схема: `prisma/schema.prisma`. Сущности из задания и решения по ним:

| Сущность | Реализация | Почему так |
|---|---|---|
| User, Role | `User`, enum `Role` (USER/EDITOR/ADMIN) | набор ролей фиксирован и зашит в проверки прав |
| Session | `Session` (sha256 токена) | серверные сессии без внешних сервисов |
| Material, MaterialType | `Material`, enum `MaterialType` | типы влияют на интерфейс; добавление типа = изменение кода |
| Category | `Category` с `kind` (SUBJECT/TASK/TECHNOLOGY) + `MaterialCategory` | три однотипных справочника, которыми управляет редакция |
| Tag, MaterialTag | как есть | свободные теги авторов |
| Research, ResearchTool, ResearchCriterion, ResearchResult | как есть + `ResearchIssue` для ошибок | критические ошибки — отдельная сущность, чтобы их нельзя было «усреднить» |
| Attachment | метаданные в БД, файл в `UPLOAD_DIR` | файлы отдаются только через проверку прав |
| Bookmark, Review, Report | как есть | отзывы и жалобы проходят модерацию |
| ModerationEvent | история статусов публикации и проверки | видна автору и редакции |
| AuditLog | журнал административных действий | отдельно от истории материала: роли, теги, жалобы |

Для каждого материала хранятся даты создания/обновления/публикации, автор, статус публикации, тип, статус проверки, источники и лицензия. Для исследования — методика (вопрос, гипотеза, условия, ограничения, исходные задания), критерии с весами и дата их фиксации, результаты, версии инструментов.

Поиск: генерируемая колонка `searchVector tsvector` (вес A — название, B — описание и задача, C — шаги, теги, примеры, категории) с GIN-индексом. Миграция: `prisma/migrations/*_init/migration.sql`.

## Система доверия

- **Статусы проверки** (`src/lib/verification.ts`) — тексты критериев и функция проверки в одном месте; страница «Методика» и сервер используют одни и те же правила. Статус меняет только редактор, и только если требования выполнены.
- **Испытания** (`src/server/research.ts`, `src/lib/scoring.ts`): результаты нельзя внести до фиксации критериев; после фиксации нельзя менять критерии и участников; опубликовать можно только с результатами, выводами и ограничениями. Оценки считаются отдельно по измерениям (техническое, педагогическое, интерфейс, ресурсы); единого балла нет; критическая ошибка определяет итог.
- **Вид проверки** (`ResearchKind`): технические возможности / оценка педагогами / результаты учеников — показывается на каждом отчёте с пояснением силы вывода.
- **Отзывы** публикуются только после модерации; на свой материал отзыв оставить нельзя.

# Как запустить сайт на своём сервере (VPS + Docker)

Инструкция для человека без опыта администрирования. Каждый шаг — это команда, которую нужно скопировать и вставить. Время: около 30–40 минут, большая часть — ожидание.

В итоге на сервере будут работать три программы в контейнерах:

- **db** — база данных PostgreSQL;
- **app** — сам сайт;
- **caddy** — «входная дверь»: принимает посетителей и сам получает бесплатный HTTPS-сертификат для вашего домена.

Данные (база и загруженные файлы) хранятся отдельно от программ и не пропадают при перезапуске и обновлении.

---

## Шаг 1. Арендуйте сервер

Подойдёт любой российский хостинг с VPS (например, Timeweb Cloud, Selectel, REG.RU, Beget, Yandex Cloud — сравните цены сами). Выберите:

| Параметр | Значение |
|---|---|
| Операционная система | **Ubuntu 24.04** |
| Память (RAM) | **2 ГБ** (с 1 ГБ сборка может не пройти — см. «Если что-то пошло не так») |
| Диск | от 20 ГБ |
| Процессор | 1–2 ядра |

После создания сервера хостинг покажет **IP-адрес** (вида `185.12.34.56`) и **пароль пользователя root** (или пришлёт на почту). Запишите их.

## Шаг 2. Подключитесь к серверу

- **Windows 10/11:** откройте «PowerShell» (меню Пуск → введите PowerShell).
- **macOS:** откройте «Терминал».

Введите (подставьте свой IP):

```bash
ssh root@185.12.34.56
```

На вопрос `Are you sure you want to continue connecting` напишите `yes` и нажмите Enter, затем введите пароль (символы при вводе не отображаются — это нормально).

Все следующие команды выполняются **на сервере**, в этом же окне.

## Шаг 3. Установите Docker

```bash
curl -fsSL https://get.docker.com | sh
```

Проверьте, что всё установилось — команда должна вывести номер версии:

```bash
docker compose version
```

## Шаг 4. Скачайте код сайта

Репозиторий на GitHub закрытый, поэтому нужен ключ доступа (токен):

1. На GitHub: аватар справа сверху → **Settings** → внизу слева **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Название — любое, срок — например 90 дней, **Repository access** → *Only select repositories* → выберите `Ryan`, в **Permissions → Contents** выберите *Read-only*. Нажмите **Generate token** и скопируйте его.

На сервере (вместо `ТОКЕН` вставьте скопированное):

```bash
git clone --branch claude/vibrant-hopper-cv2sy6 https://ТОКЕН@github.com/schoolofheroesn1-a11y/Ryan.git /opt/pedlab
cd /opt/pedlab/lab
```

> Когда ветка будет слита в основную, вместо `claude/vibrant-hopper-cv2sy6` можно указывать `main`.

## Шаг 5. Заполните настройки

Создайте файл настроек из образца:

```bash
cp deploy/env.example .env
```

Сгенерируйте два случайных пароля (скопируйте оба вывода):

```bash
openssl rand -hex 24
openssl rand -hex 12
```

Откройте файл настроек в редакторе:

```bash
nano .env
```

Заполните строки (стрелками перемещайтесь, старый текст стирайте):

| Строка | Что вписать |
|---|---|
| `POSTGRES_PASSWORD=` | первый сгенерированный пароль |
| `APP_URL=` | `https://ваш-домен.ru` — или `http://IP-сервера`, если домена пока нет |
| `SITE_ADDRESS=` | `ваш-домен.ru` (без https://) — или `:80`, если домена пока нет |
| `SEED_ADMIN_EMAIL=` | ваша почта — это логин администратора |
| `SEED_ADMIN_PASSWORD=` | второй сгенерированный пароль (или свой надёжный, только латиница и цифры) |
| `SEED_DEMO=` | `true` — если хотите сначала посмотреть сайт с примерами; `false` — пустой сайт |

Сохраните: **Ctrl+O**, Enter, затем выйдите: **Ctrl+X**.

## Шаг 6. Запустите сайт

```bash
docker compose up -d --build
```

Первая сборка занимает 5–10 минут. Когда команда завершится, проверьте состояние:

```bash
docker compose ps
```

У всех трёх строк (`db`, `app`, `caddy`) должно быть `Up`; у `app` через минуту появится `(healthy)`.

Откройте в браузере `http://IP-сервера` (или ваш домен) — должен открыться сайт. Войдите с почтой и паролем из шага 5.

## Шаг 7. Подключите домен и HTTPS

1. Купите домен у любого регистратора (REG.RU, RU-CENTER и др.).
2. В настройках DNS домена создайте **A-запись**: имя `@`, значение — IP вашего сервера. Если нужен и `www`, создайте ещё одну A-запись с именем `www`.
3. Подождите, пока запись начнёт работать (обычно 15 минут – несколько часов). Проверка: `ping ваш-домен.ru` должен показывать IP сервера.
4. В `.env` впишите `SITE_ADDRESS=ваш-домен.ru` и `APP_URL=https://ваш-домен.ru` (`nano .env`), затем:

```bash
docker compose up -d
```

Caddy сам получит сертификат за 1–2 минуты. Сайт откроется по `https://ваш-домен.ru`, а `http://` будет автоматически перенаправляться на `https://`.

## Шаг 8. Защитите сервер

Оставьте открытыми только нужные порты (SSH, HTTP, HTTPS):

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

## Шаг 9. Включите ежедневные резервные копии

Ручной запуск (копии появятся в папке `/opt/pedlab/lab/backups`):

```bash
sh deploy/backup.sh
```

Автоматически каждую ночь в 3:30:

```bash
(crontab -l 2>/dev/null; echo "30 3 * * * cd /opt/pedlab/lab && sh deploy/backup.sh >> backups/backup.log 2>&1") | crontab -
```

Хранятся 14 последних копий. **Раз в неделю скачивайте копии к себе** (на сервере они не спасут, если пропадёт сам сервер). С вашего компьютера:

```bash
scp -r root@185.12.34.56:/opt/pedlab/lab/backups ./pedlab-backups
```

Многие хостинги также умеют делать снимки всего сервера — включите их в панели хостинга.

## Повседневные действия

Все команды выполняются в папке сайта: `cd /opt/pedlab/lab`.

| Задача | Команда |
|---|---|
| Посмотреть, всё ли работает | `docker compose ps` |
| Журнал сайта (последние 100 строк) | `docker compose logs --tail=100 app` |
| Перезапустить сайт | `docker compose restart app` |
| Остановить всё | `docker compose down` (данные сохраняются) |
| Запустить снова | `docker compose up -d` |
| Удалить демонстрационные материалы перед открытием | `docker compose exec app npm run db:purge-demo` |

### Обновить сайт до новой версии

```bash
cd /opt/pedlab/lab
sh deploy/backup.sh
git pull
docker compose up -d --build
```

Изменения структуры базы применяются автоматически при запуске.

### Восстановить из резервной копии

```bash
cd /opt/pedlab/lab
docker compose stop app
# база (подставьте имя нужного файла)
docker compose exec -T db psql -U pedlab -d postgres -c "DROP DATABASE pedlab WITH (FORCE)" -c "CREATE DATABASE pedlab OWNER pedlab"
zcat backups/db_2026-10-18_03-30.sql.gz | docker compose exec -T db psql -q -U pedlab -d pedlab
# файлы
docker compose start app
docker compose exec -T app tar -xzf - -C /app/storage < backups/uploads_2026-10-18_03-30.tar.gz
```

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Сборка обрывается со словами `Killed` или `out of memory` | Мало памяти. Добавьте файл подкачки и запустите снова: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab` |
| `Задайте ... в .env` | Не заполнена указанная строка в `.env` (шаг 5) |
| `app` постоянно перезапускается | Посмотрите журнал: `docker compose logs --tail=50 app`. Частая причина — в пароле базы есть спецсимволы; используйте только буквы и цифры, затем `docker compose down -v` (⚠ удалит данные — только на новом сервере) и `docker compose up -d` |
| Сайт не открывается по домену, по IP работает | DNS ещё не обновился, или в `SITE_ADDRESS` опечатка. Журнал Caddy: `docker compose logs --tail=50 caddy` |
| Не получается войти | Проверьте, что `APP_URL` начинается с `https://`, если сайт открыт по HTTPS. Забытый пароль администратора можно сменить в кабинете; если войти совсем нельзя — напишите разработчику |
| Ошибка при скачивании образов `429 Too Many Requests` | Docker Hub временно ограничил скачивания — подождите 10–30 минут и повторите |

## Что проверено

Перед публикацией инструкции эта конфигурация собрана и запущена в тестовом окружении: сборка образа, первый запуск с созданием администратора и демо-данных, повторный запуск без повторного наполнения, вход, загрузка и скачивание файла через Caddy, сохранение данных после перезапуска, удаление демо-данных, резервная копия и восстановление базы из неё. Получение HTTPS-сертификата для реального домена в тестовом окружении проверить нельзя — оно выполняется Caddy автоматически при наличии домена, направленного на сервер.
